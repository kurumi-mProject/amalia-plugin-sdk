# Local resource storage

`FileResourceStore(privateRoot).accessFor(authenticatedIdentity)` implements the public `ResourceAccess` interface. The host retains the store administrator; plugins receive only bound access. The default policy permits the owning publisher/package/device to read and delete its immutable resources. A reference is metadata, not a bearer credential: every read chunk and delete rechecks canonical metadata and current authorization. Host grants are exact caller/resource/right scopes with expiry; they are revoked on reopening. Write creates a new UUID object and SHA-256 version. No in-place edits or implicit sharing occur.

Writes consume bounded chunks, enforce declared length, per-resource and aggregate quotas, persist data/metadata, and atomically publish a private directory. Reads verify the payload digest before emitting data. Delete persists a tombstone before moving to trash; reopening cleans unfinished writes/trash and does not resurrect tombstoned objects. An OS file lock excludes simultaneous store owners. Cancellation cleans uncommitted writes; a failure can still require reopening. Filesystem fsync and atomic rename support are mandatory. Quotas count logical file bytes, not filesystem block allocation.

This is app-private storage without application-level encryption. It is not a sandbox against trusted in-process code, a remote transfer service or a cross-device artifact database. The root and ancestors must remain private and immutable to other writers. Owner rights are package-scoped across activation instances; host grants are instance-scoped. Closing disables access and releases the lock after in-flight writers finish cleanup.
