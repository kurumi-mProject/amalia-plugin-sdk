# Библиотека шаблонов native UI Amalia

Пять небольших самостоятельных `UiDocument`, из которых удобно начинать конкретный экран. Каждый JSON можно открыть отдельно: все узлы, связи и переводы уже внутри. Это документы интерфейса, а не готовые installable-пакеты плагинов.

Сначала прочитайте [пакет автора](AI_PLUGIN_AUTHORING.md), [UI/UX-гайд](AI_UI_UX_GUIDE_RU.md) и [UI SDK](SDK_GUIDE_RU.md#14-sdk-интерфейсов-и-studio). Контракты целевого хоста приоритетнее примеров. Нужен обновлённый хост с `button`, `actions`, `list` и controls: `schemaVersion: 1` не означает поддержку этих компонентов старым APK.

## Выберите композицию

| Документ | Задача и композиция | Что подключено |
|---|---|---|
| [collection.json](examples/templates/collection.json) | Коллекция планов чтения: пояснение → список → границы примера. Без hero и метрик | Четыре статических варианта времени; локальные страницы по три строки, числовой `ITEM` binding. Выбор, создание и поиск отсутствуют |
| [controls.json](examples/templates/controls.json) | Пульт: пояснение → одна секция с группой кнопок → условия работы | Три реальных demo-вызова `advance` с фиксированными приращениями. Требуют демостенда ниже; значение счётчика здесь не отображается |
| [preferences.json](examples/templates/preferences.json) | Настройки: группа toggle/slider → радиосписок → ограничение | Локальные значения открытой `UiSession`; нет сохранения, воспроизведения звука и напоминаний |
| [form.json](examples/templates/form.json) | Короткая форма заметки: пояснение → два подписанных поля → ограничение | Строковый ввод в `UiSession`; нет отправки и хранения черновика |
| [detail-result.json](examples/templates/detail-result.json) | Детали/результат: один типографический hero → две строки деталей → статус образца | Статическая карточка плана; не подтверждает запуск плана, создание расписания или успех операции |

Во всех файлах есть полноценные `ru`, `en`, `ja`, `de`, `es`, `fr`, `zh`, `hi`, `ar`. Данные коллекции намеренно числовые: пользовательские названия и единицы переведены через `strings`, а не зашиты в массив на одном языке.

У документов пустые `sources` и `states`: они не выдумывают отсутствующие подписки. В `UiSession` без источников начальная фаза — `READY`. У list уже заданы локализованные подписи пагинации и пустого массива. Пустой массив можно получить, заменив его `LITERAL.literal` на `[]`; это состояние списка, а не автоматический переход всего документа в `EMPTY`.

## Что менять при адаптации

1. Замените `id` и `route` на IDs своего пакета, сохранив допустимые символы `[a-zA-Z0-9._-]` и начальную букву или цифру. Не задавайте caller identity через эти поля: её определяет доверенный host.
2. Перепишите задачу и строки во всех девяти локалях. `labelKey`, `titleKey`, `subtitleKey`, `valueKey`, `messageKey`, `unitKey` и ключи внутри `choices.options` содержат ключи словаря, не готовые надписи.
3. Оставьте только нужные узлы. IDs уникальны; `root`, `children`, ссылки states и `actionId` должны существовать. Удаляя узел, удалите ссылки на него. У list ровно один child — шаблон строки.
4. Для реальных данных возьмите точный descriptor provider: contract ID/version, topic, операцию, типы input/output и необходимые права. Лишь затем добавляйте `sources`, `STATE` и действия. Никакой автоматической загрузки данных из поля `route` нет.
5. Сохраните честную подпись о макете, пока соответствующая функция не реализована. Не добавляйте «Сохранить», «Поиск», «Запустить» или «Повторить» без существующей операции и проверяемого эффекта.

Не задавайте цвета, шрифты, padding, CSS, произвольные иконки или собственный фон. Тема, стекло, типографика, минимальные touch targets и insets принадлежат хосту. `section` объединяет близкие элементы; отдельное стекло каждой строке не нужно. `surface: plain` у hero карточки деталей оставляет смысловой акцент типографике. Единственная primary-кнопка находится в пульте, где есть реальная операция.

## Bindings и типы

- `LITERAL` — известное исходное значение: JSON boolean для toggle, number для slider, string для choices. У slider в примере диапазон 5–60 и шаг 5; у choices значения `silence`, `rain`, `forest` — технические идентификаторы, а подписи локализованы.
- `STATE` — объявленный `sourceId` и RFC 6901 `pointer` к реальному snapshot. Не добавляйте topic по догадке. Counter demo ниже не объявляет state topic.
- `FORM` — текущее значение контрола по его ID. Например, input заметки можно связать с аргументом будущей, реально существующей операции как `{"source":"FORM","sourceId":"body"}`. Это только способ чтения строки; контракт хранения заметок в этой библиотеке не объявлен.
- `ITEM` — текущая строка list. В коллекции `valueBinding: {"source":"ITEM","pointer":"/minutes"}` читает число из записи. Binding объекта item размещается в `properties`; основное значение list — в `value`.

`input` даёт строку, toggle — boolean, slider — число, choices — строку. Не передавайте строковый input или строковое значение choices в `advance.amount`, где требуется целое число. Нет встроенного преобразования, вычисляемых выражений или фильтрации массива. Controls внутри list запрещены: редактор записи должен быть отдельным блоком.

Начальное значение controls задавайте `LITERAL` либо реальным `STATE`, а не `FORM` на самого себя. Редактирование имеет приоритет в текущей сессии. Input в этом хосте отображает ввод из forms; шаблон оставляет поля пустыми, не обещая prefill через `value`. Текст подсказки под формой объясняет потерю черновика при закрытии.

## Кнопки и адаптивная группа действий

В `controls.json` используется новый `org.amalia.ui.button`:

- `labelKey` и `actionId` находятся на узле, не в `properties`;
- `variant`: `primary`, `secondary` (значение по умолчанию), `quiet`, `destructive`;
- `enabled`: boolean; `true` не обходит preview, grants или блокировку текущей операции;
- `icon`: одна из `auto_awesome`, `bolt`, `favorite`, `check`, `schedule`, `info`, `notification`, `play`, `search`, `mind`, `wave`, `settings`. Если иконка не нужна, свойство опускается;
- `pending` не является свойством JSON: жизненным циклом и доступностью управляет host.

`org.amalia.ui.actions` принимает только `children`, без properties. Хост размещает детей равной ширины максимум в три колонки и уменьшает число колонок с учётом доступной ширины и `152dp × fontScale` на ячейку (масштаб не ниже 1), плюс промежутки. Не фиксируйте число колонок и не предполагайте одну строку на любом телефоне.

В примере primary/secondary/quiet обозначают разные размеры одной операции, а не успех/отмену/сохранение. Вариант `destructive` не показан: разрушительной операции в demo нет. Для настоящей разрушительной операции нужен `confirmationKey` у action и его переводы во всех локалях.

## Как действительно вызвать demo advance

Точный источник: [open-contract Main.kt](../examples/open-contract/src/main/kotlin/org/example/counter/Main.kt), [описание стенда](../examples/open-contract/README.md).

| Поле | Значение |
|---|---|
| Provider | `org.example.implementation.counter` |
| Contract | `org.example.counter.counter` |
| Version | `{"major":1}` |
| Operation | `advance` |
| Input | `{"amount": integer}`; 1–10 включительно, лишние поля запрещены |
| Output | `{"value": integer}` |
| Эффект | WRITE, без идемпотентности и дедупликации |

Пульт объявляет три action с `amount` через `LITERAL`: **1**, **5**, **10**. Никаких дополнительных API нет. Демо хранит счётчик в памяти; новая активация начинает со своего initial value. Не используйте его как долговременное хранилище настроек.

Для исполнения доверенный host должен зарегистрировать contract publisher, активировать provider и выдать grant реальному caller UI на `advance` этого provider. В штатном приложении этот demo-provider не установлен. JSON-документ не устанавливает provider и не выдаёт права.

**Существенное условие identity:** исходный handler дополнительно проверяет `context.caller.packageId == "org.example.reader.client"` и наличие effective grants. В стенде используется identity publisher `org.example.reader`, package `org.example.reader.client`. Произвольный UI caller даже с похожим document ID и выданным grant не удовлетворяет проверке packageId. Для неизменённого demo UI должен работать через доверенно привязанный client этой identity с соответствующими host grants. Другой вариант — автор стенда явно адаптирует политику provider к подлинной identity своего UI и выдаёт ей права. Подмена identity строкой в JSON не работает.

JVM-пример сам по себе не подключает Android Studio UI к этому runtime. Его успешный запуск не доказывает работу кнопок из данного документа на установленном APK.

## Жизненный цикл операций и результат

Нажатие вызывает `UiSession.dispatch`; host фиксирует запрос, собирает bindings и при необходимости показывает confirmation. Пока action присутствует в operations, повторное нажатие того же action блокируется. Блокировка относится к `actionId`: три разных action пульта не образуют общую транзакцию и не блокируются одним общим флагом.

`Success` — окончательный результат конкретного запроса. `Accepted` означает принятие задачи, а `InteractionRequired` — необходимость взаимодействия; ни одно не означает завершённый бизнес-эффект. Unknown outcome нельзя безопасно повторять вслепую: у demo `advance` нет дедупликации. После окончательного ответа host может выполнить `acknowledge`; pending, accepted, interaction и неопределённые исходы остаются заблокированными до разрешения. Связанный terminal результат передаётся доверенным host через `complete` с совпадающим request ID. Отмена задачи не означает откат эффекта или разрешение повторить вызов.

В JSON нет binding к output операции и нет подписки на счётчик. Пульт намеренно не рисует `value`, progress или «Успешно». Результаты/ошибки операции показывает host. Чтобы превратить `detail-result.json` в рабочую карточку результата, сначала реализуйте достоверный путь данных: существующий state topic либо собственную проверенную проекцию результата на стороне host/provider. Не называйте статические 20 минут ответом `advance`.

## Состояния и проверка

Добавляя реальные `sources`, предусмотрите полезные `LOADING`, `READY`, `ERROR`, `DENIED`; для бизнес-сценария при необходимости `EMPTY` и `CONFLICT`. Значения `states` — IDs корневых узлов соответствующих веток, а не условия перехода. Runtime реагирует на доступность источников; пустоту бизнес-данных и конфликты сам из JSON не выводит. Ошибка action не превращает автоматически весь документ в `ERROR`. Не создавайте retry без операции и безопасной политики повторения.

Preview блокирует операции и редактирование: он показывает композицию, локали и статические данные. Поля и controls редактируются только в настоящем маршруте с `UiSession`. Preview не подтверждает сетевой доступ, grants, сохранение, поведение provider или terminal результат.

Перед использованием:

1. Декодируйте файл через `UiDocuments.decode`, затем вызовите `UiDocuments.validate(document, registry.contracts)` на целевом обновлённом хосте. Наличие корректного JSON само по себе недостаточно.
2. Откройте preview на узком экране и с крупным системным шрифтом; проверьте переносы трёх кнопок, подписи полей и арабский RTL. Проверьте светлую/тёмную тему, TalkBack, порядок фокуса, клавиатуру и safe areas на устройстве.
3. Для коллекции проверьте смену страницы и пустой массив. Для forms проверьте типы и потерю данных после завершения сессии.
4. Для пульта используйте demo host identity/grants из раздела выше. Сверьте фактический эффект каждого приращения, ошибки доступа, unavailable provider и защиту повторного вызова. Не объявляйте успех по disabled preview-кнопке.

Фактические проверки конкретной поставки и непроверенные условия следует сообщать отдельно. Эта библиотека не утверждает, что шаблоны прошли просмотр на Android-устройстве или что demo-provider подключён к приложению.
