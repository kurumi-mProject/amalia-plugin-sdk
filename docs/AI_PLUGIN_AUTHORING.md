# Пакет документации для ИИ — авторов плагинов Amalia

Начинай здесь, если задача — создать плагин с хорошим native UI/UX. Описание платформы задаёт границы возможностей, UI-гайд — композицию, JSON-примеры — точный синтаксис. Все три нужны вместе.

## Что передать модели

В таком порядке:

1. Этот файл и конкретную задачу пользователя: кто пользуется экраном, что должен сделать, какие данные реально доступны.
2. [SDK_GUIDE_RU.md](SDK_GUIDE_RU.md): раздел 14 для декларативного экрана; для исполняемого provider также разделы 4–12 и 16. Контракты из исходников целевого SDK приоритетнее предположений модели.
3. [AI_UI_UX_GUIDE_RU.md](AI_UI_UX_GUIDE_RU.md) целиком, включая списки, формы и surface.
4. [Библиотека шаблонов](UI_TEMPLATES_RU.md) и один подходящий полный пример. Не выдавай все примеры за один универсальный шаблон.
5. [Машинный контракт компонентов](UI_COMPONENTS.json): точные имена, JSON schemas, поддержка children.
6. Фактические descriptors выбранных providers: точные IDs, версии, операции, input/output schemas, state topics и необходимые grants. Если их нет, сначала проектируй provider либо честный статический preview.

Ссылки на файлы полезны модели только при доступе к репозиторию. В обычном чате приложи сами файлы. Для новых плагинов используйте только актуальные SDK3-документы из списка выше; архив совместимости не включайте в контекст модели.

## Какой пример взять

| Файл | Для чего | Что реально делает |
|---|---|---|
| [beautiful-focus-ui.json](examples/beautiful-focus-ui.json) | Типографический герой, ритм и группировка | Статическая композиция; не управляет уведомлениями или сессией |
| [preferences-ui.json](examples/preferences-ui.json) | Форма: toggle, slider, радиосписок | Локальное редактирование в смонтированной сессии; без сохранения в provider |
| [paged-list-ui.json](examples/paged-list-ui.json) | Коллекция и действие над строкой | Локальные страницы и ITEM → advance; требует demo-provider из open-contract и host grants |

Все примеры содержат девять локалей. Они обучают разным решениям: форма не обязана иметь метрики, коллекция не обязана иметь hero, статический preview не должен изображать работающий backend.

## Prompt для передачи вместе с файлами

```text
Создай плагин Amalia для следующей задачи: <описание пользователя>.
Сначала прочти приложенные SDK_GUIDE_RU.md и AI_UI_UX_GUIDE_RU.md.
Сверь API с целевой версией хоста. Используй только существующие компоненты,
properties, providers, операции и topics. Не заменяй неизвестные данные выдуманными.

До JSON сформулируй коротко:
1. Одно основное действие пользователя и критерий его завершения.
2. Источники данных и реальные контракты действий.
3. Композицию: что главное, что вторично, почему этот экран отличается
   от универсального набора карточек. Hero/метрики/бейджи — только по смыслу.
4. Путь loading → ready/empty/error/denied и восстановление, которое SDK
   действительно поддерживает. Не обещай автоматические состояния или retry.

Собери native экран на циркадном фоне Amalia. Используй surface=plain для
типографического героя, section для одной общей поверхности, item для строк.
Не вкладывай стеклянную карточку в каждую строку и каждый текст. Оставляй
воздух между смысловыми блоками. Не задавай CSS, цвета, размеры и шрифты.
Выбор вариантов — choices с радиосписком. Кнопки — button с variant
primary/secondary/quiet/destructive, группы действий — actions. Один primary максимум, если есть
реальное действие. Каждый control имеет labelKey и правильный JSON-тип.
Все строки и *Key переведи в ru/en/ja/de/es/fr/zh/hi/ar.

Выдай полный ui.json и, если нужны, components.json/provider sources/manifest
по текущему SDK. Отдельно назови зависимости и grants. Не выдавай preview за
работающую функцию. Выполни UiDocuments.validate(document, registry.contracts),
если среда позволяет; иначе прямо укажи, что эта проверка не выполнена.

Перед сдачей сократи декор и повторяющийся текст. Проверь узкую ширину,
крупный шрифт, RTL, доступность и реальные error/empty flows. Если можешь
запустить приложение, просмотри screenshots и исправь композицию. Перечисли
фактические проверки; не заявляй проверку на устройстве по одному JSON.
```

Заменяй описание задачи настоящим запросом пользователя; этот prompt — инструкция для автора, не часть UI плагина.

## Ограничения, которые модель должна знать заранее

- В декларативном UI нет произвольного Compose/HTML/CSS, обложек по URL, новых фонов, свободного позиционирования или собственного шрифта. Если требуются обложки/медиа/новая навигация, сначала расширь SDK хоста и контракт, затем пиши документ.
- `list` разбивает уже полученный массив; это не сетевой cursor, фильтрация или поиск.
- `ITEM` действует в строке и в аргументах её действия. Общая блокировка операций — по actionId.
- `input/toggle/slider/choices` внутри list пока запрещены. Отдельную форму редактирования размещай вне списка.
- `UiSession` переключает loading/ready/error/denied по источникам. EMPTY/CONFLICT не выводятся автоматически из бизнес-данных. Пустой list показывает своё empty-состояние. Ветки states сами не являются правилами определения состояния.
- Preview блокирует действия и редактирование. Настоящий маршрут с UiSession проверяет взаимодействия; сохранение формы требует операции provider.
- UI-расширения этого рабочего дерева требуют обновлённого хоста. Не объявляй поддержку на старом установленном APK только по schemaVersion=1.

## Проверка результата

Оценивай отдельно корректность контракта, полезность сценария и композицию. Валидный JSON может иметь плохой UX. Красивый preview может не иметь рабочего действия. Успех — когда оба слоя подтверждены: данные и операции связаны, экран понятен, результат и восстановление видны, на малом экране и крупном тексте сохраняется иерархия.


## Один файл для передачи модели

Из корня репозитория:

```bash
python3 tools/BuildAiUiPack.py --template preferences --output build/amalia-ui-authoring.md
```

Варианты: `collection`, `controls`, `preferences`, `form`, `detail-result`. Команда собирает prompt, UI-гайд, библиотеку композиций, точные schemas, выбранный шаблон и раздел 14 SDK в один Markdown-файл. Передай модели этот файл и свой запрос. Для рабочего плагина приложи descriptors provider и необходимые grants; пароли/API-ключи в пакет не входят. Файл назначения создаётся эксклюзивно, существующий не перезаписывается.
