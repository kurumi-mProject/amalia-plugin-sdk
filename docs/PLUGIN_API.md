# Amalia Plugin API — референс

Единый документ о том, **что такое плагин в Амалии, что ему можно, чего
нельзя и как всё это устроено**. Для авторов расширений практическое
руководство — в `EXTENSION_SDK.md`; здесь — контракт и устройство.

Ветка: `v2.0`. Версия API следует за `PluginMetadata.HOST_VERSION`.

---

## 1. Модель

**Хост — движок. Плагин — контент.** Хост не знает о конкретных расширениях:
он держит реестры, исполняет вклады и остаётся стабильным. Расширение
добавляет поведение, не трогая ядро.

| Понятие | Что это | Где живёт |
|---|---|---|
| Возможность | Что система **разрешает** делать | `capability/CapabilityRegistry.kt` |
| Особый доступ | Согласие через системный экран | `capability/SpecialAccess.kt` |
| Вклад (`Contributor`) | Новое поведение | `plugin/ExtensionPoints.kt` |
| Реестр | *Что* зарегистрировано | `plugin/PluginManager.kt` |
| Движок | *Как* это исполняется | `extension/ExtensionManager.kt` |
| Мост | Разрыв цикла ядро↔расширения | `data/ai/CommandBridge.kt` |

---

## 2. Два вида плагинов

| Вид | Что в пакете | Что умеет |
|---|---|---|
| **Декларативный** | только `plugin.json` | темы, приветственные фразы |
| **Кодовый** | `plugin.json` + `classes.dex` | любые вклады: команды, экраны, уведомления, фон, звук, движки |

Декларативный плагин не требует SDK и сборки — это чистый JSON.

---

## 3. Контракты (вклады)

Расширение реализует `AmaliaPlugin` плюс один или несколько интерфейсов.
Статус — «готово» означает, что хост исполняет вклад в рантайме.

| Интерфейс | Даёт | Статус |
|---|---|---|
| `ThemeContributor` | темы → галерея «Внешний вид» | ✅ |
| `EngineContributor` | движки STT/LLM/TTS → конвейер | ✅ |
| `ToolContributor` | инструменты → tool calling модели | ✅ |
| `PhraseContributor` | приветствия главного экрана | ✅ |
| `PromptContributor` | блоки системного промпта | ✅ |
| `CapabilityContributor` | заявляет нужные возможности | ✅ |
| `CommandContributor` | перехват фраз **до** модели | ✅ |
| `NotificationContributor` | уведомления с кнопками (нажатия переживают пересоздание процесса) | ✅ |
| `ScreenContributor` | свой экран в графе навигации + пункт в панели | ✅ |
| `WidgetContributor` | смена виджета главного экрана (волна/лампа/приветствие) | ✅ |
| `BackgroundContributor` | долгоживущее фоновое состояние (foreground-сервис) | ✅ |
| `AudioSessionContributor` | приглушение, когда говорит Амалия | ✅ |

Хосты-фасады, выдаваемые вкладам (прямого доступа к ядру нет):
`PluginContext`, `ScreenHost`, `NotificationHost` + `NotificationActionHandler`,
`AudioSessionHost` + `AudioSessionHandler`.

---

## 4. Жизненный цикл

```
onLoaded(ctx) → (onEnabled() | onDisabled())* → onUnloaded()
```

- `onLoaded` — ровно один раз на загрузку, получает `PluginContext`.
- Выключение **не выгружает** плагин из памяти; вклады уходят из реестров,
  сам плагин остаётся в списке со своими настройками.
- Все методы — на главном потоке, обязаны быть дешёвыми.

---

## 5. Возможности и разрешения

**51 возможность** в 10 категориях (`CapabilityRegistry.all`) — закрытый
список того, что Android позволяет, с указанием потребных разрешений и
готовых инструментов ядра. **12 особых доступов** (`SpecialAccessRegistry.all`)
— с обязательным предупреждением о риске. Всего **42 разрешения**
(`AmaliaPermission`).

Правила:

- Расширение **объявляет** потребность (`CapabilityContributor`), но не
  запрашивает разрешение само — запрашивает хост, показав объяснение и риск.
- Нет разрешения → вклад помечается «недоступен», приложение не падает.
- Имена инструментов в `Capability.tools` обязаны совпадать с
  `ToolDefinition.name` — на этом стоит валидация.

---

## 6. Границы доверия

1. **Не переписывать навигацию ядра** — только добавлять экраны
   (`ScreenContributor`), граф остаётся в `AmaliaNavHost`.
2. **Не трогать синглтоны ядра напрямую** — только через `PluginContext`
   и фасады.
3. **Не требовать разрешение вместо пользователя.**
4. **Не заменять конвейер** — движки меняет `EngineContributor`.
5. **Не ломать JSON-контракт ответа модели.**

Дополнительно: маршрут экрана расширения не может совпасть с маршрутом ядра
или другого расширения — конфликты отбрасываются, «первый объявивший
выигрывает» (как в реестрах тем и инструментов).

### Доверие к коду

Кодовый плагин грузится `DexClassLoader`-ом с родительским загрузчиком
приложения. Это значит: **кодовый плагин — доверенный код**, песочницы нет.
Плагин может обратиться к любому API, доступному приложению. Это осознанное
решение: подпись пакетов и ревью в магазине — отдельный слой, которого
пока нет. Пользователь, ставящий плагин, доверяет ему телефон.

## 7. Версионирование и совместимость

- `PluginMetadata.HOST_VERSION` — текущая версия API хоста (`"2.0.0"`).
- `PluginManifest.minHostVersion` — минимум, с которым совместим плагин.
  Хост старее → установка отклоняется с человеческой ошибкой.
- Сравнение версий — по числам SemVer (`PluginInstaller.isOlder`).
- **Политика стабильности:** ломающие изменения контрактов — только в
  мажоре `HOST_VERSION`. Автор плагина обязан поднимать `minHostVersion`,
  когда использует новое поле API.

## 8. Пакет `.amaliaplug`

Zip со структурой:

```
my-plugin.amaliaplug
├── plugin.json          ← обязателен
├── classes.dex          ← если есть entryPoint
└── (прочие ресурсы — читает сам плагин из PluginContext.appContext)
```

Манифест (`plugin.json`), незнакомые поля игнорируются:

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `id` | string | да | уникальный, обратный домен |
| `name` / `version` | string | да | паспорт |
| `author` | string | нет | автор |
| `category` | string | нет | `theme engine tools screen widget prompt phrases command general` |
| `description` | string | нет | одна строка для витрины |
| `minHostVersion` | string | нет | совместимость |
| `iconName` | string | нет | иконка из векторного набора хоста (`voice wave mic history lamp settings repeat copy alert close add palette engine tools screen widget prompt phrases command`); пусто — по категории |
| `entryPoint` | string\|null | нет | класс в `classes.dex`; null — декларативный |
| `themes` | ThemeSpec[] | нет | декларативные темы |
| `phrases` | map | нет | приветствия по тегу языка |

**Иконка.** Поля-эмодзи в манифесте и API **нет**. По умолчанию иконку
рисует хост единым векторным набором по категории плагина
(`.imageVector()` в `PluginRows.kt`). Эмодзи как иконки в приложении
запрещены дизайн-правилами проекта.

Необязательное поле `iconName` позволяет назвать **одну из готовых иконок
хоста** (`"lamp"`, `"history"`, …). Это не «своя картинка» и не загрузка
файла: плагин лишь выбирает из набора приложения, поэтому витрина остаётся
в единой визуальной системе — один штрих, один набор, акцент текущей темы.
Незнакомое имя — не ошибка: молча откатывается на иконку категории, так что
старый плагин на новом хосте и новый на старом работают одинаково.

## 9. Каталог и магазин

Каталог — JSON по любому URL (свой хостинг, GitHub raw, статика сайта).
Адрес по умолчанию — `https://mirabel.tech/plugins/catalog.json`.

```json
{
  "items": [
    {
      "id": "com.example.player",
      "name": "Player",
      "version": "1.0.0",
      "author": "you",
      "category": "screen",
      "description": "Плеер с фоновым состоянием",
      "downloadUrl": "https://mirabel.tech/plugins/packages/player.amaliaplug",
      "sha256": "…",
      "sizeBytes": 20480
    }
  ]
}
```

- `downloadUrl` обязателен; `sha256` рекомендован (несовпадение отклоняет).
- Приложение присылает `User-Agent: Amalia/<HOST_VERSION>` — хостинг может
  отдавать разное и вести статистику.
- Установка: скачивание в кэш → проверка sha256 → копирование в
  `filesDir/plugins/<id>/` → загрузка класса → регистрация. Любая ошибка
  откатывает установку целиком.
- Deep links: `amalia://plugin?id=…` и `https://mirabel.tech/plugin?id=…`
  открывают окно установки.

## 10. UX загрузки и установки

Спека состояний (реализуется в UI стора):

| Состояние | Что видит пользователь |
|---|---|
| Каталог грузится | skeleton-строки, не спиннер и не слово «Загрузка» |
| Каталог пуст | стеклянный медальон + действие «загрузить» |
| Ошибка сети | человеческий текст (`plugins_error_tpl`) + повтор |
| Установка идёт | диалог с индикатором; кнопка «Установить» недоступна |
| Установлено | в диалоге и строке — статус «установлено» |
| Доступно обновление | строка показывает «Обновить»; в диалоге — та же кнопка |

Загрузка витрины — **скелетон формы витрины**: заголовки групп и стеклянные
строки плагинов с бегущим блеском. Экран не «перекраивается» при приходе
каталога, а наполняет уже готовый каркас.

Установка показывает **фазу** (скачивание с процентом → проверка пакета →
установка) прямо в диалоге: пользователь видит, чего именно ждёт. Процент
показывается, только если сервер сообщил размер — выдумывать прогресс
из ничего нельзя.

Принципы: каждое состояние существует; операция идемпотентна (повтор не
ломает); ошибка — с путём восстановления.
